# 后台 UI 执行清单

更新时间：2026-06-13

## 使用方式

每次调整后台 UI 前后，按这份清单快速过一遍。  
目标不是写设计稿，而是避免继续偏离当前 `shadcn/base-nova` 系统。

---

## 1. 结构检查

- 左栏是否只承担结构导航，不承载列表筛选
- 中栏是否只承担当前上下文的文章列表
- 右栏是否只承担编辑与状态展示
- 是否删除了无信息增量的冗余标题

---

## 2. 组件检查

- 能否复用 `Sidebar`
- 能否复用 `Tabs`
- 能否复用 `Button`
- 能否复用 `DropdownMenu`
- 能否复用 `Input`
- 是否绕过了 `src/shared/ui` 现有封装

如果答案是“可以复用”，就不要写新的基础壳层。

---

## 3. 颜色检查

- 选中态是否复用了 `sidebar-accent`
- 文字是否复用了 `sidebar-accent-foreground`
- 边框是否复用了 `sidebar-border`
- 焦点态是否复用了 `sidebar-ring`
- 页面里是否又出现了新的 `sky-*` / `blue-*` active 方案

如果只是“看不清”，先调 token，不先造新颜色。

---

## 4. 交互状态检查

每个可点击对象都检查这三态：

- `hover`
- `active / selected`
- `focus-visible`

最低要求：

- hover 可感知
- selected 明确且稳定
- 键盘 focus 能看见

---

## 5. 列表项检查

文件夹项、文章项、筛选项要满足：

- 选中态是一套语言
- hover 强度一致
- 圆角一致
- 边框强度一致
- 图标和文字对齐一致

---

## 6. 可维护性检查

- 是否修改 token 就能影响一整类界面
- 是否某个页面自己长出独立状态体系
- 是否后续别人接手时能一眼知道该改哪里

如果答案是“只能在这个页面单独修”，说明设计已经开始失控。

---

## 7. 当前后台默认规则

默认按以下优先级处理：

1. 改 token
2. 改系统组件
3. 最后才改页面局部样式

不要倒过来。
