# 后台内容工作台 V2 设计方案

> 状态：已确认视觉方向，待按本文进入实现
>
> 适用范围：`/admin/posts` 后台内容工作区
>
> 本方案替代上一版“知识工作台 + 中栏状态卡片”的复杂布局，收敛为更接近笔记软件的三栏结构。

## 1. 设计目标

这轮改版只解决一个核心问题：把当前后台内容页改成一个更适合持续写作和整理的工作区，而不是继续堆叠管理型面板。

目标如下：

- 后台更像“内容库 + 文档编辑器”，而不是“文章列表 + 表单”
- 左侧结构更直观，降低用户在专题、文章、编辑器之间来回跳转的负担
- 保留现有前台发布逻辑，不改变博客页的主要展示方式
- 允许破坏性调整当前后台布局，不为兼容旧交互保留过多负担

## 2. 本轮确认的产品方向

### 2.1 整体骨架

采用固定三栏结构：

1. 第一栏：内容库与文件夹结构
2. 第二栏：当前结构下的文章列表
3. 第三栏：纯编辑器

这不是“在旧页面上继续加功能”，而是重新定义三个区域各自负责什么。

### 2.2 第一栏职责

第一栏只处理“结构”和“工作入口”，不再直接承载文章列表。

包含：

- `最近编辑 / 草稿 / 待发布` 三态切换组件
- 文件夹区块
- 专题与子专题树
- `+ 添加文件夹` 按钮

不包含：

- 展开的文章节点
- 统计卡
- 说明卡
- 复杂筛选面板

### 2.3 第二栏职责

第二栏只处理“当前上下文里的文档列表”。

包含：

- 当前选中文件夹或状态的标题
- 文章数量
- `+ 新建文档`
- 搜索
- 排序
- 文章卡片列表

不包含：

- 大面积工作流说明
- 状态概览卡
- 多层嵌套管理入口

### 2.4 第三栏职责

第三栏回到纯写作区，只保留必要上下文。

保留：

- 编辑器主体
- 当前所属结构的轻量面包屑
- `返回当前结构`
- 保存 / 发布等内容动作

移除：

- `上一篇 / 下一篇`
- `当前分支目录`
- 与编辑无直接关系的辅助卡片

## 3. 页面结构定义

### 第一栏：内容库

第一栏建议宽度保持窄而稳定，定位类似语雀、Notion 左侧结构栏，但更克制。

界面顺序：

1. 标题 `内容库`
2. 三态切换组件：最近编辑 / 草稿 / 待发布
3. 文件夹区标题
4. `+ 添加文件夹`
5. 专题 / 子专题树

交互规则：

- 三态切换和文件夹树是并列入口
- 切换到状态视图时，第二栏展示对应文章集合
- 点击专题时，第二栏展示该专题下文章
- 点击子专题时，第二栏展示该子专题下文章
- 当前选中项需要有稳定高亮

### 第二栏：文章列表

第二栏是一个轻量、可扫描的列表面板，不再承担“解释系统”的职责。

界面顺序：

1. 当前视图标题
2. 文章数量
3. 右上角操作：`+ 新建文档`、搜索、排序
4. 文章列表

文章卡片建议展示：

- 标题
- 状态（草稿 / 已发布 / 待发布）
- 最近更新时间

交互规则：

- 点击文章后在第三栏打开编辑器
- `+ 新建文档` 默认在当前上下文内创建
- 搜索默认只搜索当前上下文，后续再考虑全局搜索
- 排序先保留最基本的更新时间排序

### 第三栏：编辑器

第三栏是这次体验的重心，目标是让写作过程更安静。

界面顺序：

1. 顶部轻量上下文栏
2. 编辑器动作区
3. 标题与正文编辑区

顶部轻量上下文栏包含：

- 所属专题 / 子专题面包屑
- `返回当前结构`

编辑器动作区包含：

- 保存草稿
- 发布 / 更新发布
- 现有必要的元信息入口（按现有能力保留，不在本轮扩张）

## 4. 交互原则

### 4.1 一栏决定上下文，二栏决定对象，三栏负责编辑

这是本次重构最重要的分工：

- 第一栏回答“我现在在哪个内容结构里”
- 第二栏回答“我现在处理哪篇文章”
- 第三栏回答“我现在写什么”

任何新控件都应该优先放回它真正所属的栏目，避免再次把职责搅乱。

### 4.2 用轻量切换替代大块说明

后台当前最大的问题不是信息太少，而是有效信息密度太低。新版应优先通过：

- 切换
- 列表
- 结构高亮
- 轻量头部动作

来表达状态，而不是继续添加说明卡和状态卡。

### 4.3 维持“像笔记软件”的连续感

用户从结构切换到文章，再进入编辑，不应该产生“离开当前工作区”的感觉。

因此：

- 第二栏与第三栏需要保持同一工作流语义
- 第三栏顶部信息必须克制
- 页面不再强调后台管理感，而强调连续写作感

## 5. 与现有系统的兼容边界

本轮仅改后台工作区信息架构，不改以下内容：

- 前台博客展示逻辑
- 文章发布主流程
- 已有文章数据结构的大方向
- 编辑器核心能力

允许调整的内容：

- `/admin/posts` 页面布局
- 后台相关组件拆分
- 左右栏中的现有辅助模块去留
- 与当前布局强耦合的本地状态组织

## 6. 实现边界

本轮实现不做这些扩展：

- 拖拽排序文件夹
- 多选批量操作
- 全局搜索
- 团队协作状态
- 回收站 / 归档
- 新的前台知识库路由

这些都可以放到后续迭代，不进入当前实现范围。

## 7. 组件重构建议

建议以现有后台组件为基础做定向收缩，而不是新造一整套页面。

优先关注：

- `content-space-sidebar`
- `content-space-context-panel`
- `content-editor-shell`
- `content-space-shell`

重构方向：

- 第一栏组件专注状态切换 + 文件夹树
- 第二栏组件专注列表头部 + 文章列表
- 第三栏组件专注编辑器头部减负
- 把当前中栏大卡片、说明块、冗余导航从结构上移除

## 8. 验收标准

当满足以下条件时，说明这轮重构达标：

1. 用户进入 `/admin/posts` 后，可以一眼理解三栏分工
2. 第一栏能清楚完成“状态切换”和“文件夹选择”
3. 第二栏具备 `+ 新建文档`，且不再显得空旷无效
4. 第三栏顶部明显比当前更干净
5. `上一篇 / 下一篇` 与 `当前分支目录` 不再出现在编辑区
6. 当前页面整体更接近笔记软件，而不是传统 CMS 列表页

## 9. 测试与验证

至少需要验证：

- 专题 / 子专题切换后，第二栏列表是否正确更新
- 三态切换后，第二栏是否切到对应集合
- 新建文档是否继承当前上下文
- 点击文章后，第三栏是否稳定打开并保留必要动作
- 页面在本地 Docker 环境下可正常打开和使用

## 10. 后续迭代入口

本轮完成后，再考虑下一层优化：

- 文件夹创建与管理体验
- 列表项信息密度优化
- 编辑器元信息抽屉
- 移动端或窄屏降级策略
- 后台与前台专题感知的一致性增强
