# 后台 UI 系统规范

更新时间：2026-06-13

## 1. 目的

这份规范用于约束后台内容工作台及后台管理界面的 UI 实现方式，避免局部页面继续生长出独立的状态样式、交互层级和颜色体系。

当前后台已经基于 `shadcn/ui` 建立了一套可复用的 UI 基础层，后续优化应优先复用该系统，而不是在页面内再造一套“临时设计”。

---

## 2. 当前技术基线

项目当前 UI 基线：

- `shadcn/ui`
- `style: base-nova`
- `base: base`
- `tailwind: v4`
- `icon library: lucide`
- `ui path: src/shared/ui`
- `global token file: src/app/globals.css`

说明：

- 当前项目不是 Radix 版，而是 **Base UI 版 shadcn**。
- 组件触发器和组合方式优先使用 `render={...}`，不是 `asChild`。
- 后台界面的状态语言应优先复用：
  - `sidebar`
  - `tabs`
  - `button`
  - `dropdown-menu`
  - `input`

---

## 3. 后台内容工作台的结构原则

### 3.1 左栏

左栏只承担“结构导航”职责。

用于承载：

- 文件夹列表
- 文件夹新增入口
- 文件夹项的局部操作

不用于承载：

- 全局文章筛选
- 状态筛选
- 冗余说明性标题

结论：

- `全部 / 草稿 / 待发布` 不应放在左栏
- 左栏不再保留“内容库”这类无信息增量标题

### 3.2 中栏

中栏承担“当前上下文的文章列表”职责。

用于承载：

- 当前上下文标题（仅在有必要时显示，例如文件夹名）
- 搜索框
- 排序按钮
- 新建文章按钮
- 文章卡片列表
- 文章列表筛选器（全部 / 草稿 / 待发布）

结论：

- `全部 / 草稿 / 待发布` 属于列表筛选器，应放在中栏
- `全部文章` 这种冗余标题应删除
- 仅在进入文件夹上下文时显示文件夹标题

### 3.3 右栏

右栏承担“当前文档编辑与状态展示”职责。

用于承载：

- 文档标题
- 状态 badge
- 编辑器工具栏
- 编辑内容本体

不额外承载列表导航含义。

## 4. 选中态与状态颜色规范

### 4.1 总原则

后台所有“选中态”优先复用 **sidebar 系统 token**，不允许某个页面单独定义一套新的 active color。

统一使用：

- `sidebar-accent`
- `sidebar-accent-foreground`
- `sidebar-border`
- `sidebar-ring`

### 4.2 适用范围

以下内容都应视为同一类“后台选中态”：

- 后台主导航当前页
- 内容工作台左栏文件夹当前项
- 中栏文章卡片当前项
- 中栏底部筛选器当前项

### 4.3 不允许的做法

以下做法后续应避免：

- 页面内直接使用一套新的浅蓝色 active background
- 使用 `sky-*`、`blue-*` 作为局部页面唯一状态来源
- 通过局部盒阴影和边框单独定义“选中态系统”

### 4.4 可调整的层级

如果选中态不够明显，应优先调整 **token 本身**，而不是在具体页面里继续补更多颜色。

优先修改位置：

- `src/app/globals.css`

允许调节：

- `--sidebar-accent`
- `--sidebar-accent-foreground`
- `--sidebar-border`
- `--sidebar-ring`

---

## 5. 组件复用规范

### 5.1 必须优先复用的组件

后台内容工作台后续优先复用：

- `Sidebar`
- `Tabs`
- `Button`
- `DropdownMenu`
- `Input`
- `Badge`
- `Sheet`
- `Dialog`

### 5.2 不建议继续堆自定义壳层

以下情况应优先回到系统组件，而不是写新容器：

- 筛选切换：优先 `Tabs`
- 列表项 active：优先复用 `sidebar` active 语言
- 局部操作菜单：优先 `DropdownMenu`
- 图标按钮：优先 `Button`

### 5.3 Base UI 使用规则

因为当前项目使用 `base` 版 shadcn：

- 优先使用 `render={...}`
- 不混用 Radix 风格 `asChild`
- 修改时先看现有 `src/shared/ui` 封装，不直接跳过封装写底层 primitive

---

## 6. 内容工作台后续视觉优化顺序

后续优化建议按下面顺序推进：

1. 统一 hover / active / focus 三态节奏
2. 收紧中栏顶部高度和留白
3. 统一文件夹项、文章项、底部筛选器的圆角与边框强度
4. 统一按钮图标尺寸和触控热区
5. 最后再考虑更细的状态层级，例如已发布、草稿、待发布的视觉差异

---

## 7. 实施约束

后续后台 UI 调整默认遵守以下约束：

- 先改 token，再改组件，不先改页面局部颜色
- 能复用现有 `src/shared/ui` 就不新增自定义基础组件
- 不在单个页面内定义孤立状态体系
- 不为了“看起来更明显”引入新的主色支路
- 内容工作台应继续向“后台统一工作区”靠拢，而不是长成独立产品皮肤

---

## 8. 当前结论

当前后台内容工作台的方向没有偏离系统，最近几轮调整已经开始回收至现有 `shadcn/base-nova` 体系。

接下来的优化重点不再是“继续试一套新颜色”，而是：

- 强化系统 token
- 统一状态语义
- 收紧结构层级
- 提升可读性与可维护性
